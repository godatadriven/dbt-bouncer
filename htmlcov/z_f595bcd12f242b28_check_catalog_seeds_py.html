20def _extract_stat_value(catalog_node: Any, stat_keys: list[str]) -> int | None: 

21 """Return the first numeric stat value found on ``catalog_node`` for any of ``stat_keys``. 

22 

23 Returns: 

24 int | None: The matched stat value coerced to ``int``, or ``None`` when stats 

25 are absent or none of the supplied keys are present with a numeric value 

26 (signalling that the active adapter does not expose this stat under any 

27 of the configured keys). 

28 

29 """ 

30 stats = catalog_node.stats 

31 if stats is None: 

32 return None 

33 # ``has_stats`` is the dbt convention for adapters that emit no stats at all (e.g. DuckDB). 

34 # Access via getattr so the DictProxy's lazy wrapping returns a proxy whose ``.value`` works. 

35 # Use truthy comparison rather than ``is False`` so that any falsy adapter-side 

36 # representation (``0``, empty string, etc.) is also treated as "no stats". 

37 has_stats_entry = getattr(stats, "has_stats", None) 

38 if has_stats_entry is not None and not has_stats_entry.value: 

39 return None 

40 for key in stat_keys: 

41 if key not in stats: 

42 continue 

43 value = stats[key].value 

44 if isinstance(value, (int, float)): 

45 return int(value) 

46 return None

49@check(code="CA001") 

50def check_seed_columns_are_all_documented( 

51 catalog_node, ctx, *, case_sensitive: bool = True 

52): 

53 """All columns in a seed CSV file should be included in the seed's properties file, i.e. `.yml` file. 

54 

55 !!! info "Rationale" 

56 

57 Seed CSV files often serve as reference data (e.g. country codes, product categories) that are queried directly by downstream models. When a column exists in the CSV but not in the properties file, it is invisible to documentation tools, data catalogues, and column-level tests. This check ensures that every column in a seed is explicitly declared, making it easier for consumers to understand the seed's schema and for teams to apply descriptions and tests uniformly. 

58 

59 Parameters: 

60 case_sensitive (bool): Whether the column names are case sensitive or not. Necessary for adapters like `dbt-snowflake` where the column in `catalog.json` is uppercase but the column in `manifest.json` can be lowercase. Defaults to `false` for `dbt-snowflake`, otherwise `true`. 

61 

62 Receives: 

63 catalog_node (CatalogNodeEntry): The CatalogNodeEntry object to check. 

64 manifest_obj (ManifestObject): The ManifestObject object parsed from `manifest.json`. 

65 seeds (list[SeedNode]): List of SeedNode objects parsed from `manifest.json`. 

66 

67 Other Parameters: 

68 description (str | None): Description of what the check does and why it is implemented. 

69 exclude (str | list[str] | None): Regex pattern(s) to match the seed path. Seed paths that match any pattern will not be checked. 

70 include (str | list[str] | None): Regex pattern(s) to match the seed path. Only seed paths that match any pattern will be checked. 

71 severity (Literal["error", "warn"] | None): Severity level of the check. Default: `error`. 

72 

73 Example(s): 

74 ```yaml 

75 catalog_checks: 

76 - name: check_seed_columns_are_all_documented 

77 ``` 

78 

79 """ 

80 if catalog_node.unique_id is not None and catalog_node.unique_id.startswith( 

81 "seed." 

82 ): 

83 seed = next(s for s in ctx.seeds if s.unique_id == catalog_node.unique_id) 

84 

85 if ctx.manifest_obj.manifest.metadata.adapter_type in ["snowflake"]: 

86 case_sensitive = False 

87 

88 seed_columns = seed.columns or {} 

89 if case_sensitive: 

90 undocumented_columns = [ 

91 v.name 

92 for _, v in catalog_node.columns.items() 

93 if v.name not in seed_columns 

94 ] 

95 else: 

96 seed_columns_lower = {c.lower() for c in seed_columns} 

97 undocumented_columns = [ 

98 v.name 

99 for _, v in catalog_node.columns.items() 

100 if v.name.lower() not in seed_columns_lower 

101 ] 

102 

103 if undocumented_columns: 

104 fail( 

105 f"`{get_clean_model_name(seed.unique_id)}` has columns that are not included in the seed properties file: {undocumented_columns}" 

106 )

109@check(code="CA002") 

110def check_seed_max_bytes( 

111 catalog_node, 

112 *, 

113 max_bytes: Annotated[int, Field(gt=0)], 

114 byte_stat_keys: Annotated[list[str], Field(min_length=1)] = [ # ruff: ignore[mutable-argument-default] 

115 "bytes", 

116 "num_bytes", 

117 "size", 

118 ], 

119): 

120 """Each seed must not exceed the given size in bytes. 

121 

122 !!! info "Rationale" 

123 

124 Seeds are checked into version control and reloaded by every dbt run, so very large CSV files inflate repository size, slow seed runs, and signal that the data probably belongs in a source table instead. This check enforces an upper bound on seed size so that the project does not accumulate oversized reference data. 

125 

126 !!! note 

127 

128 Seed size is read from the catalog's per-relation stats, which are populated by the warehouse adapter. The default `byte_stat_keys` cover the adapters whose source has been verified: `dbt-snowflake` (`bytes`), `dbt-bigquery` (`num_bytes`), `dbt-redshift` (`size`), and `dbt-databricks`/`dbt-spark` (`bytes`, parsed from `DESCRIBE TABLE EXTENDED`). The first key found on the catalog node wins. 

129 

130 For any other adapter — e.g. `dbt-athena`, `dbt-fabric`, `dbt-trino`, `dbt-clickhouse`, `dbt-synapse`, `dbt-singlestore`, `dbt-vertica`, etc. — inspect the relevant entry in `catalog.json` to find which key (if any) holds the byte count, then supply it via `byte_stat_keys`. If the adapter emits no byte stats at all the check will raise a `RuntimeError`. 

131 

132 Parameters: 

133 max_bytes (int): The maximum number of bytes permitted for a seed. 

134 byte_stat_keys (list[str]): Ordered list of stat keys under `stats.<key>.value` to try when extracting the seed's byte count. Defaults to `["bytes", "num_bytes", "size"]`, which covers the verified adapters. Override to support additional adapters. 

135 

136 Receives: 

137 catalog_node (CatalogNodeEntry): The CatalogNodeEntry object to check. 

138 

139 Other Parameters: 

140 description (str | None): Description of what the check does and why it is implemented. 

141 exclude (str | list[str] | None): Regex pattern(s) to match the seed path. Seed paths that match any pattern will not be checked. 

142 include (str | list[str] | None): Regex pattern(s) to match the seed path. Only seed paths that match any pattern will be checked. 

143 severity (Literal["error", "warn"] | None): Severity level of the check. Default: `error`. 

144 

145 Raises: 

146 RuntimeError: If the active adapter does not expose any of `byte_stat_keys` in the catalog. 

147 

148 Example(s): 

149 ```yaml 

150 catalog_checks: 

151 - name: check_seed_max_bytes 

152 max_bytes: 1048576 

153 ``` 

154 ```yaml 

155 # Overriding the keys for a hypothetical adapter that exposes ``size_bytes``. 

156 catalog_checks: 

157 - name: check_seed_max_bytes 

158 max_bytes: 1048576 

159 byte_stat_keys: 

160 - size_bytes 

161 ``` 

162 

163 """ 

164 if catalog_node.unique_id is None or not catalog_node.unique_id.startswith("seed."): 

165 return 

166 

167 bytes_used = _extract_stat_value(catalog_node, byte_stat_keys) 

168 if bytes_used is None: 

169 raise RuntimeError( 

170 f"`{get_clean_model_name(catalog_node.unique_id)}` does not expose any of " 

171 f"{list(byte_stat_keys)} in catalog stats. If your adapter emits byte " 

172 "stats under a different key, set `byte_stat_keys` accordingly. If it " 

173 "emits no byte stats at all, this check is not supported for that adapter." 

174 ) 

175 

176 if bytes_used > max_bytes: 

177 fail( 

178 f"`{get_clean_model_name(catalog_node.unique_id)}` has {bytes_used} bytes, " 

179 f"which is greater than the permitted {max_bytes}." 

180 )

195 

196 !!! info "Rationale" 

197 

198 Seeds are intended for small reference datasets such as lookup tables, country codes, or feature flag values. As row counts grow, seeds become slow to load, awkward to review in pull requests, and prone to drift from authoritative upstream systems. This check enforces an upper bound on row count so that large datasets are surfaced as a source or external table instead of a seed. 

199 

200 !!! note 

201 

202 Row count is read from the catalog's per-relation stats, which are populated by the warehouse adapter. The default `row_stat_keys` cover the adapters whose source has been verified: `dbt-snowflake` (`row_count`), `dbt-bigquery` (`num_rows`), `dbt-redshift` (`rows`), and `dbt-databricks`/`dbt-spark` (`rows`, parsed from `DESCRIBE TABLE EXTENDED`). 203 

204 For any other adapter — e.g. `dbt-athena`, `dbt-fabric`, `dbt-trino`, `dbt-clickhouse`, `dbt-synapse`, `dbt-singlestore`, `dbt-vertica`, etc. — inspect the relevant entry in `catalog.json` to find which key (if any) holds the row count, then supply it via `row_stat_keys`. If the adapter emits no row stats at all the check will raise a `RuntimeError`. 

205 

206 Parameters: 

207 max_row_count (int): The maximum number of rows permitted for a seed.

209 

210 Receives:

212

216 include (str | list[str] | None): Regex pattern(s) to match the seed path. Only seed paths that match any pattern will be checked.

218

221 

222 Example(s):

224 catalog_checks:

226 max_row_count: 1000 

227 ``` 

228 ```yaml 

229 # Overriding the keys for a hypothetical adapter that exposes ``record_count``. 

230 catalog_checks:

233 row_stat_keys:
